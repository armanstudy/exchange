### Table style tokens (receipt)
- Border: single **0.5 pt** (`sz=4`) `#B9C2CE` on all edges + inside.
- Cell padding: top/bottom 55 tw (**2.75 pt ≈ 1 mm**), left/right 90 tw (**4.5 pt ≈ 1.6 mm**); table cell margin default 10 tw.
- Label cell: bg `#EEF2F7`, bold navy 11 pt, vertical center. Value cell: bg `#F5F8FB`, `#1A1A1A`, center (for numbers/dates) or start-aligned (text).
- Label/value column widths: 1500 tw (26.5 mm) / 3319 tw (58.5 mm); payer name label 1900 tw (33.5 mm).
- Spacer paragraphs between blocks: 5 pt font, after 2 pt.

### Number / date formats in the receipt
- Digits: **Latin** digits almost everywhere; Persian digits only in signature dates («۱۴۰۵»). Mixed — recommend picking one (open question).
- Thousands separator: **dot** `.` → `13.000.000.000`, `1.500.000.000`; rate `38.595 تومان`; equivalent `33.683 یوان`.
- Units: amount in **ریال**, conversion rate in **تومان** per RMB (13,000,000,000 IRR = 1,300,000,000 Toman ÷ 38,595 = 33,683 RMB). Amount in words: «سیزده میلیارد ریال».
- Dates: Jalali **dd/MM/yyyy** (`12/07/1405`, `08/07/1405`); signature date `dd / MM / yyyy` with spaces.
- Bank tracking numbers: free text of varying length (5–18 digits, e.g. `11824`, `292355`, `14050708191038777`).

## 6. Receipt number analysis (OPEN QUESTION — not decided)

Numbers seen:
- In the document body: **`YI140507126LE`** (field «شماره رسید»; typed as three runs `YI14050` + `7126` + `LE`).
- In the uploaded file name: **`140507012`** («رسید دریافت وجه - 140507012.docx»).
- Receipt date: `12/07/1405`. Bank deposit dates: 08/07/1405 and 09/07/1405.

Plausible interpretations (**ask the user**):
1. `YI` = Yiwu prefix, `14050712` = Jalali date yyyyMMdd (1405/07/12), `6` = sequence of the day, `LE` = LEnj suffix.
2. `YI` + `140507` (yyyyMM) + `126` = running sequence within the month/year + `LE`.
3. File name `140507012` = yyyyMM (`140507`) + 3-digit sequence `012`; or yyyyMM + zero-padded day `012` (day 12). Body and file name disagree, so one of them may be a draft/old number.
4. Prefix/suffix may encode branch (YI = Yiwu office vs. a future TE/Tehran) and company (LE).

Questions for the user: Which is canonical? Is the sequence per day, per month, or per year? Does it reset? Is the prefix branch-dependent? Should Persian or Latin digits be used?

## 7. Customer statement (صورتحساب) analysis

Generator: FastReport PDF export, A4 portrait (595.5 × 842.25 pt), 5 pages, tagged PDF. Text layer has a broken ToUnicode map for digits (pdftotext produces garbage like `14@0/@0/h6`), so all observations below come from the rendered pages. Only black/grey/white — no brand colour.

**Page 1 header (letterhead)**: right: issuer Persian name (bold, large) + captions `تلفن :`, `فاکس :`, `صندوق پستی :`, `ایمیل :` (grey `#808080`); left: Latin short name `WBI` + `Tel :`, `Fax :`, `P.O.Box :`, `Email :` + address line (Istanbul); center: logo. Then a horizontal rule.

**Report title**: «صورت حساب» centered, bold.

**Report parameters** (two lines): right: `ارز : همه ارزها` (currency filter: all), `نمایش : از تاریخ 1405/01/01 الی 1405/07/20` (date range); left: `دوره : 2022` (fiscal-period code), `چاپ : 1405/07/20` (print date).

**Account line (repeated on every page)**: `حساب : <customer name>` (right) · `شماره : <10-digit account no.>` · `نوع حساب : مشتریان` · `صفحه : N / M` (left). Page numbering format **`صفحه : 1 / 5`**.

**Column order (RTL, right → left)** — repeated header on every page, bold, underlined by a rule:

| # | Column | Content |
|---|---|---|
| 1 | `سند` | doc type (small, e.g. انتقال / فروش ارز / دریافت بانکی / پرداخت بانکی) over **bold doc number** (e.g. 13819, 5406, 584) |
| 2 | `تاریخ` | Jalali `yyyy/MM/dd` over Gregorian `(yyyy/MM/dd)` in parentheses |
| 3 | `شرح` | description (wraps up to 3 lines) |
| 4 | `ارز` | ISO-ish code: `IRR`, `USD`, `TRY` (centered) |
| 5 | `بدهکار` | debit |
| 6 | `طلبکار` | credit |
| 7 | `مانده` | running balance **per currency**, with suffix: `بس` (بستانکار = creditor, we owe customer) or `بـد` (بدهکار = debtor); `0` with no suffix when settled. Large values wrap (suffix on 2nd line). |

- Numbers: **Latin digits, comma thousands separator** (`1,885,000`, `4,000,000,000`), right-aligned; zeros shown as `0`. FX rates with many decimals (`230,800.30004039`, `4,240.2077701807`).
- Rows grouped into **bordered blocks per transaction date** (thin black box around each date group), with **alternating row shading `#F0F0F0`** inside the block.
- Currency exchange (`فروش ارز`) creates **two rows with the same doc number**: one per currency leg (e.g. IRR debit + USD credit).

**Description patterns** (structure only):
- `انتقال` (plain transfer); `انتقال , <name>`; `انتقال از <bank> <name>`; `انتقال به سپرده <account> <bank> <name> ( IRR )`.
- `هزینه انتقال - انتقال` (transfer fee, separate row, same doc no.).
- `فروش USD 10 نرخ 188,500 ( IRR 1,885,000 ) به <customer>` → pattern **`فروش {CUR} {amount} نرخ {rate} ( {CUR2} {equivalent} ) به {customer}`**.
- `واریز به <account> <bank> (<label>) <name> ( IRR )- تراکنش<ref>` (bank receipt).
- `انتقال به … - تراکنش<ref>` (bank payment).

**Final summary «مانده حساب»** (last page, centered bold title, then a borderless table, bold numbers):

| ارز | مانده قبلی | مجموع بدهکار | مجموع بستانکار | مانده نهایی | شرح |
|---|---|---|---|---|---|
| one row per currency (IRR, TRY, USD) | opening balance | total debit | total credit | closing balance (absolute) | `بدهکار` / `بستانکار` |

## 9. Implications for the app

**PDF receipt** (must match `Receipt-Template.docx`):
- A4, same margins, 170 mm content width, RTL, B Nazanin (embed a licensed font or Vazirmatn as fallback).
- Letterhead exactly as §5 (logo, EN name, FA name in `#41282E`, two-column China/Iran contact block with 1 pt navy bottom rule).
- Navy title bar and section bars with the same labels; label/value grid with `#EEF2F7`/`#F5F8FB` fills and 0.5 pt `#B9C2CE` borders.
- Currency checkboxes (ریال ایران / دلار – USD / یوان – RMB) and method checkboxes (نقدی / کارت به کارت / حواله بانکی / چک) rendered as 5 mm squares, filled black when selected.
- Fields: receipt no., date (Jalali), payer name, phone, national ID, address, amount (digits), amount in words, conversion rate (unit Toman), equivalent (e.g. RMB), list of bank deposits (bank, amount, tracking no., date), purpose text, two signature blocks, fixed footer sentence + EN name.
- Validate that deposits sum to the receipt amount (true in sample). Keep signature block unsplittable (`cantSplit`).
- Configurable: receipt number format (open question §6), digits (Latin vs Persian), separator (`.` in receipt vs `,` in statement).

**PDF statement**:
- Use LENJ letterhead/colours (not WBI's). Keep the statement *structure*: title, parameters (currency filter, date range, print date), account line with page `N / M` repeated every page, repeated column header.
- Columns RTL: سند (type + number) · تاریخ (Jalali + Gregorian) · شرح · ارز · بدهکار · طلبکار · مانده (per-currency running balance with بس/بد suffix).
- Group rows by date, zebra shading; FX deals as two legs with one doc number; fee rows separate.
- Final per-currency summary table: ارز · مانده قبلی · مجموع بدهکار · مجموع بستانکار · مانده نهایی · شرح (بدهکار/بستانکار).

**WPF theme**:
- Primary brush `#0B2F5B` (title bars, primary buttons, DataGrid headers with white text); accent `#41282E` sparingly (brand name); surfaces `#FFFFFF` / `#F5F8FB` / `#EEF2F7`; borders `#B9C2CE` / `#D9DFE6`; text `#1A1A1A`, secondary `#526174`, tertiary `#6B7A8C`.
